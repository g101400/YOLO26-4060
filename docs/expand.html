扩展更多类别与分割

把 COCO 80 类基线，扩展到「更多目标的识别 + 实例分割」。三种路线，按成本与诉求选择

路线 A：开放词汇检测（不训练，直接扩类别）

YOLO-World / Grounding DINO / OWL-ViT

用文本提示检测任意类别，无需重新训练。适合 80 类覆盖不到的长尾与临时需求。
零样本即开即用
• YOLO-World：与 YOLO 同族，社区已有 ncnn/ONNX 导出，端侧可行性最高。
• Grounding DINO / OWL-ViT：Transformer，精度高但更重，宜放云端做「检测→VLM」前置。
落地：把 YOLO-World 导出的 ncnn 模型放入 assets/，复用现有 anchor-free 解码器（v8/v11/v26 同构）即可在 app 内加载。

路线 B：微调自有数据（最稳，扩你关心的类）

在 YOLOv8/v11/v26 上微调

收集你的目标数据（标注）→ ultralytics 微调 → 导出 ncnn → 丢进 app。
高精度领域适配复用解码器
关键：v8/v11/v26 输出布局一致，C++ 解码器零改动，只换模型文件。v5 因锚框范式需单独分支。
自动标注降本：见「结合大模型改进」→ 用 VLM 预标 + 纠错，回流再训练。

路线 C：实例分割（识别 + 像素级轮廓）

YOLOv8-seg / YOLO11-seg

在检测框之外输出掩码（mask），可做面积统计、缺陷区域、抠图。
像素级需改解码器
改动点：① 导出 seg 模型（proto + 框）；② C++ 解码器增加 mask 分支（反卷积 proto → 上采样 → 按框裁切）；③ OverlayView 增加掩码绘制；④ 类别数随训练数据变化。
现状：当前安卓端为纯检测（box）。分割为下一步工程，需一次 native 重构 + 重编，但架构已预留（同一套加载/回调框架）。

安卓端集成脚手架（通用）

1. 模型文件放 app/src/main/assets/（如 yoloworld_ncnn_model/）。
2. Ncnnv5lite.loadModel 已支持按 id 加载，新增一类模型只需在 modeltypes[] 与 model_array 加一项。
3. anchor-free 系列（v8/v11/v26）解码器可复用；seg 需扩展 yolov8.cpp 的 decode_anchorfree。
4. 类别名表在 CocoLabels.java，扩类时同步扩展即可（或在 assets 放 labels.txt 动态读取）。

建议的推进顺序

① 先用 YOLO-World（路线 A） 验证「更多类别」需求，零成本；
② 沉淀自有数据，走 微调（路线 B） 提升领域精度；
③ 需要轮廓/面积时，上 seg（路线 C），重构一次解码与绘制。
