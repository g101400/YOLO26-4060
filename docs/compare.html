二、五个维度拆解

① 检测速度：v5 唯一基于锚框，需预设锚框聚类；v8 起三代为 anchor-free。同精度下 v11 比 v8 快一截（FLOPs 更低），v26 再快约 43%（官方，去 NMS + 结构精简）。选 320 档最快、640 档最准。

② 精度：nano 档随代际递增（34→37→39.5→40.3）。趋势是「同尺寸精度↑、算力↓」。v11 靠注意力换小目标/遮挡鲁棒性；v26 主要靠小目标（STAL）与端到端简化拉开差距。

③ 原理创新性：v5=C3+PANet（范式偏老）；v8=解耦头+全 anchor-free（现代化起点）；v11=C3k2+C2PSA 注意力；v26=回归链路做减法（去 DFL、去 NMS）+ 训练侧创新（ProgLoss/STAL/MuSGD），方向从「堆结构」转向「为边缘部署做减法」。

④ 工程应用场景：v5 适合接手存量/不追新；v8 生态最繁荣（检测/分割/姿态/OBB 全任务）；v11 适合小目标、遮挡、复杂背景且要省算力；v26 适合纯边缘、低功耗、小目标密集、要求低延迟易部署。

⑤ 源代码（本仓库实情）：v5 安卓用老一套 锚框解码器（native lib 名 libncnnv5lite，类 Yolov5）。v8/v11/v26 三者 ncnn 输出布局完全一致（in0→out0，(84,N)，前 4 通道为 cx/cy/w/h 绝对像素、后 80 通道已是 sigmoid 后类别概率），故 C++ 解码器是同一份代码复用，仅 JNI 里 modeltypes[] 改成 yolo11n_*/yolo26n_*、包名/applicationId/版本号不同。所有模型均为 COCO 80 类。

三、怎么选

• 求稳、求生态、接老系统 → v8（或 v5）。
• 要更好精度/小目标、还想控算力 → v11。
• 最新、边缘 CPU 极致速度、小目标密集、部署越简单越好 → v26。
• 现实建议：四个 APK 都齐了，不要二选一，按场景换模型——同一套安卓壳，v8/v11/v26 直接换 ncnn 模型即可（v5 因解码不同需走单独分支）。高算力手机跑 640 档，老机/实时跑 320 档。

四、能否结合大模型改进

能，而且很值得。当前是「YOLO 出框 + ncnn 端侧实时」，大模型（VLM/LLM）属「语义理解+决策」层，两者互补不替代：开放词汇检测、自动标注、自然语言查询、提示式智能体、缺陷可解释、小样本适配。详见 「结合大模型改进」 子菜单，以及 app 内已内置的「VLM 分析」功能。
